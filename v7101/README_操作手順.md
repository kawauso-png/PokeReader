# スイクン v7.10.1 候補試験版

UPを押す前の状態を選び、実際に生成された個体値まで確認する版です。候補表示は色違い確定ではありません。実機での成功率向上・待ち時間は未検証です。

## 入れ替え

3DSの電源を切り、既存の `default.3gx` をバックアップしてから、本版の3GXを `default.3gx` に改名し、SDの `/luma/plugins/0004000000172500/` に置きます。既存の `/luma/plugins/pokereader/` にあるBINとtracesはそのまま利用します。

## 1回の操作

1. 日本語VCクリスタルを起動し、これまでログを取っていた「UP入力でスイクンイベントへ進む直前」の同じ位置・状態にします。PokeReaderのRNG画面を表示します。
2. **START＋SELECT** で停止し、**Y＋十字キー下**を押したら、すべて離します。`S7101 CANDIDATE SCAN` で自然な進行を待ちます。
3. **`S7101 CANDIDATE READY`** で止まったら、**Bを押して離します**。UPはまだ押しません。
4. **`S7101 CANDIDATE ARMED`** が表示されたら、**UPだけを押し続けます**。
5. **`TWO UP POLLS COMPLETE / RELEASE UP`** が表示されたら、**UPを離します**。M14で自動再開するので、そのまま待ちます。
6. 実際の個体値を取得すると自動停止します。**`SHINY - CATCH IT!` ならリセットせず、STARTで再開して捕獲**してください。`NOT SHINY` なら手動でVCをリセットしてやり直します。

`ARM MISMATCH` または `INPUT ARM FAILED` は入力準備の不一致です。UPを押さず、手動でやり直します。候補待ちが長い場合はHOMEからゲームを終了できます。待ち時間の上限は保証していません。

CSVは従来どおり自動保存します。新しい `PRE7101` 行に候補チェック数、除外数、入力前の照合結果を残します。表の約8.98%という数値は全状態に対する候補の割合であり、色違い率ではありません。

## この版で確認できていること

- 元のv7.10.0生成ソースは、提示されたSD上の3GXと同じGitHub成果物に含まれていました。
- 16ログすべてで、入力前の3フレームの状態遷移が一致しました。
- 候補表は65,536状態すべてで順方向のモデル計算と一致しました。
- 入力は従来の物理UP・FFA4 Exact2・M14を使います。新しいRandomフック、RNG/DIV/DVの書換え、入力生成は追加していません。

その先の経路は観測済みデータから作った仮説です。異なるRNG状態で同じ経路を通る保証はなく、未観測の分岐もあります。モデルの対象外に本当の色候補がある可能性もあるため、本版を成功実証済みの乱数調整ツールとは扱わないでください。
