# 色違い予測に必要な情報を集める v7.10.2

目的は、入力前の状態から最終個体値までを予測できるように、未確定の分岐を調べることです。この版は候補を選別せず、同じ入口条件からデータを収集します。

## 最初は3回

同じ開始位置・操作で、**BASE → TAIL → DEEP** を1回ずつ記録してください。途中ではゲームのセーブを更新せず、各回が終わったら従来どおり手動リセットします。予期せず色違いが出た場合はリセットせず捕獲できます。

| 回 | READY画面で選ぶ表示 | 取る情報 |
|---|---|---|
| 1 | BASE | 入力前RAMと通常のログ。比較基準 |
| 2 | TAIL | 入力前RAM＋途中の分岐付近のCPU・音楽・HRAM |
| 3 | DEEP | 入力前RAM＋最終個体値生成付近の乱数呼び出し・CPU・音楽・HRAM・ARMレジスタ |

3本で法則が決まるという意味ではありません。最初に記録の欠落、Exact2/M14、観測の負荷を確認し、次の収集条件は結果に合わせて絞ります。通常モードと詳細モードは別の試行なので、違いが出ても観測のせいだとは即断しません。

## 毎回の操作

1. 日本語VCクリスタルを起動し、これまでログを取っていた「UPでスイクンのイベントを始める直前」の同じ位置・状態にします。PokeReaderのRNG画面を表示します。
2. **START＋SELECT** で停止し、**Y＋十字キー下**を押して、すべて離します。
3. **S7102 BASE READY** で止まります。**X**で `BASE → TAIL → DEEP → BASE` と切り替わるので、その回のモードを選びます。
4. **Bを押して離し**、すべてのキーを離したまま **S7102 RECORD ARMED** を待ちます。入力前RAMを保存する準備は自動です。
5. **UPだけを押し続けます。** `TWO UP POLLS COMPLETE / RELEASE UP` が出たらUPを離します。M14で自動再開します。
6. **S7102 BASE/TAIL/DEEP DONE** と **CSV OK 番号** が出れば、その回の記録完了です。メモするならモードと番号だけで十分です。
7. 3回終わったら、3DSの電源を切ってSDをMacへ戻し、「3回終わった」と伝えてください。こちらで新しいCSVを読み、不足していた変数との対応を調べます。

`CAPTURE FAILED`、`INPUT ARM FAILED`、`CSV ERR` が出たら、その回は成功扱いにせず中止して表示を伝えてください。エラー時も保存できた入力前スナップショットがあれば解析します。

`SHINY - CATCH IT!` が出た場合はリセットせず、STARTで再開して捕獲してください。

## 自動で残るもの

従来と同じ `/luma/plugins/pokereader/traces/celebi_trace_番号.csv` に、`R7102_META`、`R7102_BLOB`、`R7102_SAMPLE` を追加します。ファイル名はCelebiのままですが、内容はスイクンの記録です。手動での数値入力や別ファイルの作成は不要です。

全モードで、入力前と終了時のC000–DFFFのRAM、FF80–FFFEのHRAM、64バイトのエミュレータCPU領域を記録します。これはROMやセーブの書換えではありません。実行中に詳細を取るTAIL/DEEPでは、コピー開始・終了時刻とDIV/subtickの変化も記録し、そのデータを通常モードと区別します。

詳しいモードの結果は、従来の自己校正BINへ混ぜません。全モードで物理UP・Exactly 2 polls・M14を維持し、実際の個体値まで進めます。
