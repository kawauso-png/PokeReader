# v7.10.10 一括クロック収集版

この版は診断用。色違い候補の選別は行わず、最初に見つかった従来の入力条件で1回イベントを進める。最終DVと、そこまでの全RNG読み取り・タイマー割り込みを同じトレースに記録する。

1. クリスタルを起動し直し、いつものスイクン直前位置・停止状態のRNG画面で **Y＋↓**。すべてのボタンを離す。
2. **`S7110 CLOCK RECORD READY`** が出たら **↑だけを押し続ける**。
3. 再停止したら↑を離し、従来どおりイベントとCSV保存の完了まで待つ。
4. できた **新しい `celebi_trace_....csv` を1本**回収する。まず1回でよい。rank7108_scanファイルを待つ必要はない。

開始地点を探している間はSELECTで停止できる。通常の最終DVが出ても、この試行では失敗ではない。自然に色違いが出た場合は既存のSHINY表示に従い捕獲できる。

## 一度に記録する内容

- 開始時のRAM・IO・エミュレーター状態、既存の経路記録、最終DV。
- 全通常RNG更新とDV生成のDIV読み取りごとに、DIV値・残りカウント・バッチ経過値を記録。
- 同じ地点のTIMA/TMA/TAC、タイマー位相、割り込み設定、LCD状態。
- タイマー割り込み入口（日本語ROM 3E25でのFFE9読み取り）の記録。
- 各記録時点までのLCD割り込み回数。長いLCD処理は別カウント。

R7110_CLOCKは最大4096件。上限超過や読み取り中の値の変化は隠さず記録し、解析側で不完全な試行として扱う。実機中は固定バッファへの記録だけで、SD保存や文字列整形は停止後に行う。

RNG・DIV・DV・セーブの書き換え、合成↑入力は追加していない。物理↑、Exact2、M14の処理を維持する。ただし観測を追加した実行なので、新しい記録で経路の整合性を検証する。

## 過去データで分かったこと

元モデルの古い位相値はバッチ経過値を含み、物理位相と同じではない。最新4件の最終DV付近では差が最大47 M-cycleあった。また、±1更新を最後へ追加・削除する近似では、途中の演出時間の違いを正しく表せない。

過去9件を対象に、対象試行自身を参照から外して再構成モデルを試したところ、平均約355候補に6件の実測DVが含まれた。元の比較用モデルは平均約374候補で2件。まだ十分狭い予測ではなく、設定の開発に既存データを使っているため、実機成功率とは解釈できない。今回その試作モデルを色選別に搭載していない。

既存ログには通常更新の残りカウントが途中約730回分そろっておらず、タイマー割り込みも直接記録されていない。その不足を1試行でまとめて補うための版。
