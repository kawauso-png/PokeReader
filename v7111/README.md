# v7.10.11：VC内部状態の追加収集

色違いを判定して止まる予測版ではありません。VC処理の再実行で不足と判明した、内部I/O変換表・定数表・VCのメモリ状態を、入力前に停止した状態でまとめて保存する診断版です。

## 実機で行うこと

1. 更新後、ゲームを再起動します。
2. いつものスイクンイベント直前の位置で、乱数画面を停止します。
3. **Y＋↓**で開始し、いったんすべてのボタンを離します。
4. **S7111 STATE RECORD READY**が出たら、これまでと同じように**↑だけを押し続けます**。
5. 再停止したら↑を離し、イベント終了とログ保存を待ちます。
6. 新しくできた**celebi_trace_XXXX.csvを1本**渡してください。

追加状態は同じCSVに入ります。保存量が従来より最大約5MB増えるため、保存完了までSDを抜かずに待ってください。候補探索を長時間待つ必要はありません。

## 何を確認するデータか

0031の保存情報だけで、VCのCPU処理と時計処理を使った最初のDIV読み取り2回を再現できました。その後に読む内部I/O変換表の実体が旧ログに含まれていなかったため、再実行を停止しています。

今回追加するのは、native code末尾の次から002FFFFFまでの読み取り可能ページと、WRAMのホストアドレスを含む1MiBのVCヒープ領域です。ページ単位で読み取り可能性、個別チェックサム、全体の件数と保存末尾を検査します。停止中のCPU・時計・WRAM・IOとの一致と、3種類のI/O表が保存範囲にあることも確認します。

RNG・DIV・DV・セーブデータへの書き込みは行いません。物理↑のExactly2、M14の処理とv7.10.10の時計観測を維持しています。追加コピーはPREの停止中だけで、イベント進行中のフックに大量コピーを追加していません。

追加バッファを収めるため、プラグインのメモリ枠は5MiBから10MiBへ変更しています。生成ファイルの設定とメモリ使用量も確認してから配布します。

この1本で色違いが出ることや、すべての再実行依存データが必ず揃うことを保証するものではありません。まず既存情報では読めなかった具体的なVC状態を補い、推測で埋めずに再実行を進めるための収集です。

## 解析側

`python3 -B v7111/extract_snapshot.py trace.csv --out memory_pages` で追加ページを検証・展開できます。未記録ページをゼロで補完しません。`memory.json`に既知のアドレス・ファイル・SHA256を保存します。CLOCK行はv7110の検査器を引き続き使用できます。
