# v7.10.12：RTCを含む事前入力でDVを予測するための版

0032は、保存したVC状態とROMに「操作開始時の本体時刻」を加えることで、通常731回＋最終3回、1468回のDIV値・乱数状態・読み取り時刻・割り込み回数がすべて実測と一致し、最終DV C672まで再実行できました。開始時刻を前後1秒変えても同じ結果でした。

ただし0032の開始時刻は事後のHRAMから補ったため、独立した事前予測の成功とは扱いません。この版は不足していた入力直前の本体時計情報を、ゲームがまだ停止している間に自動保存します。色候補を選んで止まる実機機能はまだありません。

## 今回行うこと

1. 更新後、ゲームを再起動します。
2. いつものスイクン直前の位置で停止し、Y＋↓を押します。
3. すべて離し、「S7112 RTC RECORD READY」が出たら↑だけを押し続けます。
4. 再停止したら↑を離し、イベントとCSV保存の完了を待ちます。
5. 新しいCSVを1本渡してください。

時計を手動で変更したり、時刻をメモしたりする必要はありません。RNG・DIV・DV・セーブへの書き込み、実機への合成↑は行いません。Exactly2とM14は維持しています。

## 追加される入力

R7112_RTC stage 0はPRE停止時、stage 1は物理↑を検出した後、ゲームを再開する直前の記録です。各記録は3DSの時刻参照ページ（1FF81000、4096バイト）、コピー前後の本体tick、安定性フラグ、チェックサムを含みます。参照値がコピー中に更新された場合は最大3回再試行します。

解析ツールはNATIVE_CODE・PREのCPU/WRAM/IO・凍結ページ・ROM・stage 1だけを読み、実測DIV列・最終DV・END・後続FRAMEを予測入力に使いません。VC自身の時刻変換処理を再実行して開始時刻を求めます。未記録メモリの読み取りは失敗として止めます。

`prepare_replay.py --trace trace.csv --rom captured_vc_rom.bin --out input` で入力を検証・抽出します。旧0032の再検証に限り、明示的に`--allow-missing-rtc`と事後補完したRTC差分97秒を使用します。

native_replay.cはMac上のUnicorn用の検証器です。実機プラグイン内では実行しません。RTCを開始時の値に保つ仮定、描画バッファ選択を固定する仮定があり、0032での一致のみを確認済みです。HEADLESSモードの描画省略も0032の全DIVで同じ結果でした。別条件や将来の実機で成功率を保証するものではありません。

## 0033で判明した制約（2026-09-08追記）

実測結果を読む前に保存した予測は43E9、実測は43E8で、独立した最終DV予測には失敗しました。開始時RTCを固定する仮定は一般には使えません。0033ではExactly2再停止を挟むframe 2→3に2.908秒の経過があり、その後ゲーム内時計が分をまたぎます。記録されたFRAME時刻を与えてRTCを進める事後検証では、1470回のDIV値・乱数状態・位相・LCD/TIMERカウンターすべてが一致しました。未記録FRAME時刻には補間を使っており、これを事前予測の成功には数えません。

`check_rtc_sensitivity.py --trace trace.csv --rom captured_vc_rom.bin --out new_directory` は、開始前の入力だけを抽出し、動作速度30/60fpsと再停止待ち0/1/3/5秒の8仮説を比較します。0033では43E8と43E9の両方が得られ、時計依存の不安定さを検出できます。この有限個の比較は全時間経路を網羅せず、3/8などを成功確率として扱うこともできません。色候補を選んで実機で停止する機能はまだありません。

native_replay.cの追加環境変数RTC_SCHEDULE_FILEは、1100行の`frame,packed_hex`で仮説時刻を指定するオフライン検証用です。run_prediction.pyはこの変数を環境から除去するため、従来の固定RTC予測に検証用設定が混入しません。実機コード、Exactly2、M14、SD上のv7.10.12は今回変更していません。
