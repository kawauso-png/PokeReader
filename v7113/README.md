# v7.10.13 — 色候補を選んで停止する実験版

Y＋↓で探索します。過去モデルで絞り込んだ開始状態を、コピーしたVC状態のC実行器で先読みします。時計の進行30/60fpsの2条件のいずれかで色DVが出れば停止します。これは有限条件での候補選択であり、実機の成功率は未測定です。過去モデルの絞り込みで本当の候補を見落とす可能性もあります。

## 操作

1. ゲームを再起動し、いつものスイクン直前の位置で停止します。
2. **Y＋↓**を押したら、すべてのボタンを離します。
3. `SEARCHING`は探索中、`CHECK ... MODEL ... FRAME ...`は先読み中です。先読みは重い処理です。画面のFRAMEが進む間はボタンを離して待ちます。SELECTで中断できます。
4. **`TRY SHINY DV ...`**とカウントダウンが出たら候補停止です。残り5秒になり`HOLD UP NOW UNTIL PAUSED`が出たら、↑だけを押し続けます。0秒で実入力の受付を始めます。
5. **`RELEASE UP`**が出たら↑を離します。開始から約5秒後の予約済みM14で自動再開します。再開まですべてのボタンを離してください。
6. 戦闘結果とCSV保存を待ちます。色違いなら捕獲してください。外れた場合は、新しい`celebi_trace_*.csv`と`shiny7113_*.csv`を解析に使えます。

候補待ち中のSELECT・入力期限切れは、ゲームを停止したまま候補を取り消します。↑入力前ならY＋↓で探索し直せます。`RELEASE TOO LATE`または`KEYS AT RESUME`になった場合は、イベントへの入力が始まった後なので、VCをリセットして元の位置からやり直します。

## 実装

- `arm_core.c`：ARM命令をCで解釈。メモリ操作はすべてコールバック経由。
- `shadow.c`：既存の非公開スナップショットを作業用に使い、VC自身のゲーム処理を先読み。ROM/コードは読み取り専用。仮説間と本番前に実機の状態を撮り直す。
- `gate_runtime.c`：過去モデルの広い絞り込み（rank≤2048、support≥1）後に、先読み結果で候補を判定する。順位だけでは停止しない。通常更新の固定値や±1補正で色を偽装しない。
- 最初の短い実行で計算速度を測り、計算が終わる余裕を持って入力時刻を予約する。開始時の自然なゲーム内RTCの秒が10になる時刻を選ぶ。時計自体は変更しない。
- Exactly2の物理↑確認を維持し、再停止後のM14再開時刻をあらかじめ予約する。予約時刻にボタンが残っていれば再開しない。
- 実機のRNG・DIV・DV・セーブへの書き込み、合成↑、Legal Advanceは使わない。

## 検証と限界

0032の1468件と、時計の進行を事後補完した0033の1470件で、C版の乱数値・状態・位相・LCD/TIMER回数が既存実行器と一致しました。0033の独立した固定RTC予測が43E9、実測43E8だった事実は変わりません。

コピー上だけで作った色DV6AAAのテストでも1470件がUnicornと一致しました。これは実機での色成功ではありません。ARMのレジスタ・条件・フラグ・シフト等4256件をUnicornと比較しました。候補選択、仮説の実行失敗、状態の変化、期限切れ、ボタン制限とM14の順序もテストしています。

3DS上の探索速度・候補頻度・色成功率は未測定です。計算期限を超えると`ERROR 00711302`で停止します。未対応の命令や読めないメモリでも停止します。有限個の時計条件や過去モデルは、すべての実機経路を保証しません。
