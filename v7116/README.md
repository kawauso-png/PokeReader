# v7.10.16 — 先読みの高速化と開始状態の自動保存

Y＋↓からの操作と、色候補の判定条件はv7.10.15と同じです。実機のRNG・DIV・DV・セーブを書き換えず、↑は物理入力を使います。

## 改善

- 頻繁に実行されるARM命令を、同じ命令をまとめて処理するCコードで実行します。使用前に全対象命令を照合し、異なる場合は従来の実行器へ戻ります。RTC・LCD・入力など既存の観測箇所は省略しません。
- 7条件のコピー再生で、乱数列・仮想命令数・最終メモリが従来版と一致しました。Mac上の速度は約2.5〜2.9倍になりました。3DS上の倍率は未測定です。
- 本格的な先読みの直前に、使用する開始状態と予約した時計条件を自動保存します。エラーや予測外れを、追加の手動トレース操作なしで解析するためのファイルです。
- 1回の探索につき約3MiBの `shiny7116_pre_探索ID.bin` を作り、次の本格的な検査で上書きします。ヘッダーに検査番号があるので、CSVのどの検査か区別できます。ROM本体は保存しません。読み込み時には完全性と各領域のハッシュを確認します。
- 保存に失敗しても、それだけで色候補の判定結果を変更しません。CSVの `GATE7116_PRE` に保存成否を記録します。

`GATE7116_CPU` の末尾には高速化の有効フラグ・高速化した仮想命令数・処理回数・コード不一致位置が加わりました。これで実機でも高速化が有効だったか確認できます。

## 操作

1. VCを再起動し、S7116の表示を確認します。
2. いつものスイクン直前の位置でY＋↓を押し、すべてのボタンを離します。
3. SEARCHINGやCHECK/MODEL/FRAMEの間は待ちます。SELECTで中断できます。
4. TRY SHINY DVとカウントダウンが出たら、残り5秒のHOLD UP NOW UNTIL PAUSEDで↑だけを押し続けます。
5. RELEASE UPが出たら↑を離し、自動再開と戦闘結果を待ちます。
6. エラー・通常色の場合は、同じ探索IDの `shiny7116_*.csv` と `shiny7116_pre_*.bin` を一緒に解析に使えます。戦闘まで進んだ場合は新しい `celebi_trace_*.csv` も使えます。

RELEASE TOO LATEやKEYS AT RESUMEの場合は、VCをリセットして元の位置からやり直します。候補待ち中のSELECTは↑入力前ならY＋↓で探索し直せます。

## 検証と残る課題

3,198件のブロック実行を従来の1命令ずつの実行と比較し、レジスタ・フラグ・メモリ・エラーが一致しました。コード変更時のフォールバック、DV代入の両バイト確認、古い色DVを採用しないこと、保存の途中失敗や破損ファイル拒否も検証しています。

既存の合成色DV6AAAはコピー上だけのテストです。実機の色成功を意味しません。0033で固定時計予測が43E9、実測が43E8だった問題も解決済みとは扱いません。有限の時計仮説と過去モデルによる絞り込みは引き続き不確実で、実機の色成功率は未測定です。

自動保存ファイルはVCのプログラムやゲームの作業メモリを含む解析用データです。ソースリポジトリにコミットせず、手元で扱います。
