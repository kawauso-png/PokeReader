# v7.10.17 — 開始位置を広く探索して、色DVの実書き込みで停止

**Y＋↓で探索を開始し、TRY SHINY DVが出るまで待ちます。** 最初の基準位置で停止した後は、入力なしで2フレームずつ進めながら、ほかの開始位置も調べます。64検査ごとに3フレーム進め、同じ偶奇だけを調べ続けることを避けます。

## 画面の意味

- **SPEED TEST**：最初の速度測定です。
- **PRE 1/2・2/2**：コピー内で先頭65フレームを実行し、残りの経路から色になる可能性を絞り込んでいます。
- **FULL 1/2・2/2**：DVが実際に書き込まれるまでコピー内で実行しています。2条件のいずれかで実際の色DVが確認できれば、候補として停止します。
- **SEARCHING**：次の開始位置へ進みます。開始位置を細かく調べるため、ADVが2〜3ずつ増える動作になります。画面更新や計算が続いている間は待ってください。
- **TRY SHINY DV**：入力前の候補停止です。まだ実機のスイクンが生成されたわけではありません。

PREの経路モデルだけでは停止しません。±8の仮説は候補の絞り込みにだけ使い、FULLでは補正値を加えず、コピー内に実際に書き込まれたDVを判定します。PREに候補がなくても64検査ごとにFULLを実行し、モデルの見落としも調べます。

## 操作

1. VCを再起動し、S7117の表示を確認します。
2. いつものスイクン直前の位置でY＋↓を押し、すべてのボタンを離します。
3. TRY SHINY DVとカウントダウンが出たら、残り5秒のHOLD UP NOW UNTIL PAUSEDで↑だけを押し続けます。
4. RELEASE UPが出たら↑を離し、自動再開と戦闘結果を待ちます。
5. エラーや通常色の場合は、同じ探索IDの `shiny7117_*.csv` と `shiny7117_pre_*.bin` を解析に使います。戦闘まで進んだ場合は新しい `celebi_trace_*.csv` も使います。

開始状態は自動保存されます。1回の探索につき約3MiBで、次の本格的な検査やエラー時に更新します。検査番号・時計条件・ハッシュが入っています。ROM本体は含みません。

SELECTで探索・候補待ちを中断できます。↑入力前ならY＋↓でやり直せます。RELEASE TOO LATEやKEYS AT RESUMEの場合は、VCをリセットして元の位置からやり直します。

## 今回の根拠

過去の実機コピーを入力なしで待機させた開始状態から、RNG・DIV・DVを書き換えず、開始時刻の仮説を合わせることで6AAAが生成されました。従来の実行器と独立したUnicornの双方で実際のDV代入を確認し、全1466件の乱数ログも一致しました。

この開始位置は、以前のA/r10・bucket76固定の探索では対象外でした。そこで固定位置・過去順位だけによる除外をなくし、先頭の正確な実行と、その後の完全実行を組み合わせました。新しい経路集合は、この色候補と同じPREを除いた通常色の経路だけで構成しています。

高速化はv7.10.16の命令照合・不一致時の従来処理への復帰を維持しています。Mac上では約2.5〜2.9倍でした。3DS上の倍率と候補頻度、実際の色成功率はまだ未測定です。固定時計で待機した古いコピーと、30/60fpsの有限な時計仮説による検証であり、現在の実機の全経路を保証するものではありません。

実機のRNG・DIV・DV・セーブは書き換えません。↑は物理入力、受付はExactly2、再開はM14です。
